MethodologyAdding comparisons

Public evidence schema

Each comparison publishes reviewed schema-version 2 JSON. The homepage reads a generated schema-version 1 comparison manifest.

Comparison records

  • Stable ID/slug, title, participants and encounter metadata.
  • Requested and normalized calendar windows, canonical timezone and evidence freshness.
  • Verified shared report/fight records, conservative shared session clusters and individually verified activity.
  • Candidate evidence, coverage limitations and explicitly discontinuous coverage windows.
  • Aggregate reports/fights examined and scope-specific latest-status verification.

Fight evidence

Records contain report code, fight ID, encounter ID, absolute UTC/local timestamps, confirmed target actor IDs, participant keys, result, verification description and a direct FFLogs fight link. Report-specific actor IDs are not global character or Lodestone IDs.

Unknown is not zero

No observed activity is represented by an empty observation array and null first/last timestamps. It does not imply verified inactivity. Report/fight counts describe examined evidence, not all actual raid participation. Different uploads can contain duplicate evidence of the same physical pull.

What is excluded

No credentials, tokens, OAuth headers, raw authenticated API caches, complete player rosters, private source code, database files, unrelated report inventories or vault documents are published. Public JSON is a curated projection, not a raw API dump.
